# B06a AI Capability 내부 검증 경계

AI 담당자와 Spring↔FastAPI 요청·응답 JSON을 확정하기 전에도 B는 추천 엔진에 전달될 Capability 후보를 안전하게 검사할 수 있다. `AiCapabilityIntake`는 전송 형식이나 성공 상태를 정의하지 않는 **내부 도메인 경계**다.

입력은 Capability 후보의 고정 ID·필수/선택/미정 분류·이유·근거 필드와 추가 질문, 그리고 **A가 신뢰된 스냅샷 계약에서 제공한 허용 필드 경로 집합**이다. 허용 집합을 AI 응답에서 가져오면 검증이 무력화된다. ID는 합의된 9개만 허용하며, 빈 후보 목록(질문만 있는 경우 포함)·중복 ID·중복 근거/질문 필드·빈 이유·알 수 없는 근거/질문 필드·필수/선택인데 근거가 없는 후보를 거부한다. 검증 결과는 입력 목록의 변경에 영향받지 않는 불변 복사본이다.

검증 결과의 `requiredCapabilityKeys`와 `hasUndeterminedCapability`는 B 추천 입력을 구성하는 자료일 뿐이다. 빈 결과나 미정 결과를 추천 성공으로 해석하지 않는다. A의 확인된 Profile·미해결 충돌, HTTP/LLM 성공 여부, 응답 JSON의 추가 필드, 질문 주체, 오류·재시도 계약은 별도로 확인해야 한다. 여기서는 DB 저장과 공개 API를 연결하지 않는다.

`RecommendationInputAssembler`는 검증 결과를 추천 엔진 입력으로 옮기는 내부 연결부다. AI의 생략 의미가 미합의인 동안 **9개 키가 모두 평가된 경우에만** 필수·미정 값을 전달한다. 일부 키만 평가된 결과는 `NO_ADDITIONS_NEEDED`로 해석될 수 있으므로 차단한다. A의 미해결 충돌, 현재 환경 대상, 선언 설치 버전은 별도 신뢰 입력으로 받아 복사한다. 이는 전송 계약을 확정하거나 AI 응답의 9개 전량 반환을 합의했다는 뜻이 아니다.

완료 확인: 중단 전 작성한 테스트를 먼저 실행해 구현 누락을 확인했고, null 필드 오류 테스트를 추가해 실패를 본 뒤 수정했다. `mvn clean verify`에서 85개 테스트 발견, 84개 통과, Windows 심볼릭 링크 테스트 1개 건너뜀. B06 전체는 AI와 전송 계약을 합의하고 엄격한 파서·실패 응답 처리·A 스냅샷 연결을 마칠 때까지 미완료다.
