# 프론트엔드 대비 로컬 데모 기능 점검 — 2026-10-18

## 판정 기준

- **브라우저 확인**: 로그인한 `/app/live`에서 실제 Core API, AI 서비스 또는 PostgreSQL 결과를 확인한 것.
- **코드·자동 테스트 확인**: 경로와 계약 및 테스트는 확인했으나 이번 점검에서 브라우저의 성공·실패 양쪽을 직접 실행하지 않은 것.
- **미연결/제한**: `/demo` 디자인에는 있으나 실서비스 화면 또는 API에 연결되지 않은 것.

현재 실행 중인 컨테이너는 Web, Core API, AI 서비스, PostgreSQL이다. Web 소스는 `apps/web`; 프론트엔드 독립 저장소 로컬 `D:/capstone/Frontend`의 `main` `0c39dad`가 반영돼 있다. `npm test -- --run` 80/80, `npm run lint`, `npm run build`가 통과했다. 이 프론트 테스트 중 다수는 `/demo`의 메모리 시연 모델을 검증하므로 API 통합 테스트로 해석하지 않는다.

## 가장 큰 데모 위험

1. **서로 다른 두 화면의 오인:** `/demo/projects/...`의 10단계는 메모리 시연이다. 실제 API 경로 `/app/projects/:id/...`는 각 단계 디자인 화면 대신 `/app/live?project=id` 한 화면으로 이동한다. 발표 시 디자인 화면에서 DB 저장·추천·ZIP까지 되는 것처럼 보여주면 실제 기능과 다르다.
2. **실제 도구 추천 오인:** 현재 추천·ZIP은 데모 Catalog를 사용한다. skills.sh 후보를 받아왔다고 곧바로 안전한 설치 도구로 추천하지 않는다.
3. **분석 자료 저장 후 새로고침:** 서버에 기획 자료가 있어도 화면은 저장 여부를 복원하지 않아 `AI 분석 시작`이 비활성화된다. 발표는 자료 저장 후 같은 화면에서 분석을 시작하거나 다시 업로드해야 한다.
4. **AI 원문 근거 검증:** Solar가 원문에 없는 인용을 반환하면 `INVALID_PROVIDER_OUTPUT`으로 실패한다. 한국어 1페이지 PDF·명확한 Markdown은 성공했지만 영문 PDF 일반 동작은 입증되지 않았다.

## 후속 우선순위

1. 서비스의 단계별 디자인을 실제 API 상태에 연결할지, `/app/live`를 데모의 공식 화면으로 쓸지 결정하고 발표 동선을 하나로 고정한다.
2. 저장된 기획 입력의 분석 가능 상태/재시도 표시를 서버 상태와 함께 복원한다. A API의 입력 메타데이터 제공 여부를 먼저 협의한다.
3. 실서비스 역할·환경 필드와 B 계약을 제품 요구사항에 맞춰 좁혀 확정한다. 프론트 시연 필드를 그대로 저장 필드로 간주하지 않는다.
4. 실제 도구의 OS·Client·권한·설정 출력을 검증해 Catalog에 승인하고, 비추천·추가 질문·실패 및 적용 보고 경로를 브라우저에서 별도 확인한다.

## 2026-10-19 후속 작업

`/app/live`의 현재 프로젝트 영역에 이름 변경과 이름 재입력 방식의 삭제 폼을 추가했다. 두 요청은 현재 프로젝트 버전을 전송한다. 이름 변경은 임시 프로젝트 `f8c78fc7-e063-49e2-af48-3dd3bdd723b9`에서 `PATCH` 후 버전 `1 → 2`, 목록과 새로고침 후 이름 유지까지 확인했다. 이 임시 프로젝트는 삭제하지 않고 남겨 두었다. A의 프로젝트 PATCH는 기존 Profile 이름을 함께 변경하지 않으므로, 이름 변경 폼은 기획 자료·분석·Profile이 없는 새 프로젝트에만 표시한다. 삭제 폼은 정확한 현재 이름을 입력하기 전에는 비활성화되며, 실제 `DELETE` 성공은 아직 브라우저에서 확인하지 않았다.

프론트 최종 변경 기준 `npm test`는 83/83, lint와 빌드는 통과했다. Core 삭제 테스트는 소스에서 확인했지만 현재 호스트에 Maven 실행 파일이 없어 이번 후속 작업에서 새로 실행하지 못했다. 2026-10-19 재확인 시 Docker 엔진도 중지돼 있어 이름 변경 제한을 추가한 뒤의 브라우저 재검증은 미실행이다.
