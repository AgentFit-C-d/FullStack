# 별도 AI needs 계약 수용 계획

**목표:** B가 별도 AI 저장소의 검색용 `needs` API를 정확한 요청·응답 형식으로 호출하고 근거를 검증한다. 검색용 needs를 9종 Capability 판정으로 오인하지 않는다.

**범위:** B 소유 Java 클라이언트와 테스트, Claude Code 실물 Skill 1종의 버전·권한·조합 근거 재검토. A 분석 Worker와 AI 서버 소스는 수정하지 않는다.

## 작업

1. B의 확정 입력 경로를 별도 AI의 `field:index` fact ID로 변환하고 역방향 근거표를 보존한다. 허용되지 않은 필드, 과대 입력은 요청 전에 거부한다.
2. Bearer 인증, `deadline`, `budget.targetId/leaseId`를 포함해 `POST /internal/v1/skills/needs`를 호출한다. AI 응답의 검색어·근거 ID·개수를 검증하고 원래 A/B 경로로 되돌린다. 오류는 계약·입력·공급자·전송으로 구분한다.
3. 로컬 HTTP 계약 테스트에서 정확한 요청과 근거 위조·인증 실패 응답을 확인한다.
4. 실물 Skill 후보의 고정 파일 해시, 정확한 Claude Code 버전, 권한 범위, 단독 조합 및 미검증 범위를 기록하고 후보 검증기를 실행한다.

**완료 한계:** 별도 AI의 `needs[]`에는 필수/선택/미정 판정이 없다. 기존 추천 생성기의 9종 Capability 입력에는 연결하지 않는다. A의 예산 lease 발급과 AI의 9종 판정 계약이 마련돼야 실제 추천 종단 연결이 가능하다. 팀 독립 승인 전에는 실물 Skill을 운영 카탈로그에 활성화하지 않는다.
