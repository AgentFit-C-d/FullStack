# 풀스택 B 상위 12개 기능 점검 — 2026-10-26

## 기준과 숫자

기준은 `D:/capstone/Docs/team-prds/full-stack-b/PRD.md`의 **FSB-01~12**다. `Docs/fullstack-b/STATUS.md`의 B01~B12는 별도 내부 구현 단계이므로 합산하지 않는다. 현재 연결된 화면은 `/app/live`이며, 독립 Frontend 저장소의 단계별 화면을 모두 실 API에 연결했다는 뜻은 아니다.

- **코드 흐름:** FSB 7개(02, 03, 06~10)는 핵심 경로를 구현·검증했고, 5개(01, 04, 05, 11, 12)는 부분 구현이다. 이는 **7/12(약 58%)의 기능 경로**라는 뜻이지 제품 완성률이 아니다.
- **실제 Claude Code 도구를 갖춘 운영 종단 완료:** **0/12**. skills.sh 실물 Skill 1종을 Windows/Claude Code 2.1.270에서 국소 검증했으나 팀의 독립 승인 전이다. 실제 AI 응답은 테스트 작성과 실행을 모두 필수로 판단하고 검증 후보는 작성만 지원한다. 10월 27일 격리 DB 종단 테스트에서는 부분 추천 1건과 미충족 경고를 저장·조회했다.
- **이번 변경:** 서비스 화면이 백엔드의 기본/선택 후보, 추천 이유, 출처, 검토 위험도·외부 인증, 만료된 추천의 저장 당시 항목을 표시한다. 선택 후보는 기본 선택하지 않고 명시 선택 시에만 Preview 권한 요청에 포함한다. AI가 아직 OPTIONAL을 반환하지 않아 선택 후보의 실제 AI 종단 화면은 검증하지 못했다.
- **후속 FSB-12 보강:** 현재 승인 카탈로그가 없어지거나 파일 검증에 실패해도 과거 추천 GET은 저장 당시 항목을 `STALE` 조회용으로 반환한다. 현재 Catalog 근거·권한은 붙이지 않으며 새 Preview/승인은 기존 승인 검사를 그대로 거친다. 이는 이력 조회의 가용성 개선이며 새 도구의 승인이나 실사용 검증을 뜻하지 않는다.
- **2026-10-27 FSB-04 보강:** 전체 필수 기능을 충족하는 구성부터 찾고, 없으면 실제 지원·조합·정적 출력 검증을 통과한 후보 중 충족 기능이 가장 많은 부분 구성을 `RECOMMENDED`로 저장한다. `partial_required_coverage` 경고와 Preview의 `unmetCapabilityKeys`를 유지한다. 아무 검증 후보도 해당 기능을 제공하지 않으면 `NO_COMPATIBLE_TOOLS`다. 로컬 검토용 TDD Skill은 테스트 작성만 충족하므로 테스트 실행을 미충족으로 남긴다. 실제 FastAPI needs→B 추천→격리 PostgreSQL 저장→Preview HTTP 검증을 통과했으나 독립 승인을 대신하지 않는다.
- **2026-10-27 Client 버전 보강:** 로컬 Claude Code `2.1.310`에서 기존 고정 Skill의 테스트 작성 동작을 재확인하고 [별도 검토 후보](../catalog/obra-tdd-2.1.310-local-review-2026-10-27.md)를 만들었다. `2.1.270` 승인 해시를 변경하거나 운영 설정에 넣지 않았다. Java/Maven Skill 호출 및 새 후보의 종단 검증은 완료되지 않았다.

## 증거와 다음 우선순위

- 실제 AI 응답과 PostgreSQL 추천 결과: [실물 Skill 샘플](real-catalog-sample-2026-10-26.md). AI 별도 저장소와 Core 사이의 분석 계약 불일치도 이 문서에 기록했다.
- 기능 경로와 기존 한계: [B 인터페이스 점검](2026-10-25-b-interface-audit.md). 구현 현황은 `services/core-api/src/main/java/com/agentfit/coreapi/catalog`, `recommendation`, `configuration`, `apps/web/src/features/live` 참조.
- 이번 화면 연결은 프론트 테스트 **96/96**, lint, build를 통과했고 로컬 컨테이너의 `/app/live` 및 새 JS가 HTTP 200으로 제공됨을 확인했다. OPTIONAL 실응답·실물 추천 성공을 증명한 것은 아니다.

우선순위는 (1) 독립 검토를 마친 실도구 Catalog 확대, (2) A/AI와 실제 분석·OPTIONAL 계약 정렬, (3) 여러 Capability를 충족하는 실제 추천→Preview→ZIP 종단 검증, (4) 단계별 서비스 화면의 API 연결이다. 실물 Skill 후보를 자동으로 승인 Catalog에 승격하지 않는다.
