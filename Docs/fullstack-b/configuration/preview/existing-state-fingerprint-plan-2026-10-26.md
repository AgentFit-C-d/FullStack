# 기존 설정 상태를 미리보기 승인 지문에 포함

## 문제와 결정

`UNKNOWN`과 `USER_SAYS_EMPTY`는 모두 기존 파일 bytes가 없어 같은 `PROPOSAL` 파일 목록을 만든다. 현재 지문은 파일·선택·정책만 해시하므로 이 두 입력 상태를 구분하지 못한다. PRD FSB-10의 입력 변경 재확인 원칙에 맞춰 `existingState`를 최종 승인 지문에 포함한다. 파일 내용·원본·Diff의 저장 범위는 늘리지 않는다.

## 구현 순서

1. 같은 선택·파일이라도 `UNKNOWN`과 `USER_SAYS_EMPTY`의 지문이 달라야 한다는 실패 테스트를 작성한다.
2. `PreviewFingerprint.compute`와 저장 메타데이터 재계산 경로에 `existingState`를 전달하고 최종 지문에 반영한다.
3. 기존 지문 고정 벡터를 새 형식으로 갱신하고 저장·조회·승인 관련 회귀 테스트를 실행한다.
4. 기존 방식으로 생성된 미리보기는 재계산 시 거부된다. 사용자는 미리보기를 다시 생성해 승인한다. B5–B9 이력 및 원본 파일은 변경하지 않는다.

## 검증 기록

- `UNKNOWN`과 `USER_SAYS_EMPTY`가 같은 지문으로 계산되는 실패를 먼저 재현했다.
- 수정 후 지문·비교·미리보기 생성·Catalog 조립·승인·ZIP 관련 순수 Java 테스트 50개가 통과했다.
- PostgreSQL opt-in 테스트는 Docker가 꺼져 있어 실행하지 못했다. 승인 컨트롤러 테스트는 로컬 Java 24의 Mockito 에이전트 초기화 문제로 통과 여부를 확인하지 못했다.

## 경계

A·AI·Frontend 소스는 수정하지 않는다. 이미 생성된 ZIP 내용이나 추천 결과 자체에는 영향을 주지 않는다.
