# 풀스택 B 다음 작업과 인계 경계

[현재 체크리스트](STATUS.md)의 미완료 항목을 실제 연결 순서로 묶었다. 앞 단계에 필요한 A·AI 입력이 준비되기 전에는 공개 API나 실제 설정 다운로드를 완료로 표시하지 않는다.
[A·AI 연동 계약 제안](integration/ab-ai-contract-proposal.md)에 현재 B 코드가 요구하는 필드와 팀 합의가 필요한 쟁점을 정리했다. 이 제안은 확정 계약이 아니다. 1차 실제 Catalog는 Claude Code부터 검증하고 Codex는 후속으로 둔다.

| 순서 | 작업 | 필요한 외부 입력 | 완료 판정 |
| --- | --- | --- | --- |
| 1 | A 현재 스냅샷 계약 확정 (B05·B09) | 인증 사용자/프로젝트 소유권, CONFIRMED Profile·Review·Developer·Environment 버전, 확인 이벤트, 현재 추천 소속 | B가 읽은 basis와 요청 시점의 현재 basis를 대조할 수 있음 |
| 2 | AI Capability 계약 확정 (B06) | 고정 9개 키, 필수/선택/미정, 질문 주체, 오류·재시도 형식 | 미지 키·제외 필드·실패 응답을 저장 전 거부 |
| 3 | 실제 Catalog 릴리스 검증 (B08) | 대상 Client·OS·정확한 버전의 공식 근거, 템플릿/권한 매핑/조합 검토, 독립 승인 해시 | 검토된 조합만 활성화; 미검증은 비활성 |
| 4 | 인증된 읽기 API와 B 메타데이터 영속화 (B05·B07·B12) | A의 인증·오류 응답·트랜잭션·삭제 규칙 | 소유권 검사, 추천/선택/이력 저장, 삭제 연동 통합 테스트 |
| 5 | Preview·승인·다운로드 연결 (B10·B11) | 현재 basis 재확인, 추천 소속, 승인/만료/감사 저장 계약 | 동일 입력 재생성·지문 일치 시에만 Preview된 파일 bytes를 ZIP으로 반환 |

구현 전 반드시 재확인할 제한:

- `CatalogPreviewAssembler`는 호출자가 **A가 확인한 현재 basis와 환경 대상**을 전달한다고 가정한다. 이 클래스 자체가 인증·소유권·추천 소속을 조회하지 않는다.
- Preview 조립은 전달받은 저장 추천의 상태·ID·basis·선택 도구 소속을 검사한다. 하지만 그 저장 추천과 현재 basis를 **A의 소유권 검사된 조회**로 확보하는 연결은 아직 없다.
- 승인 Catalog 해시는 브라우저나 릴리스 매니페스트에서 받아 신뢰하면 안 된다. 검토 후 서버 설정 또는 신뢰된 저장소에서 독립적으로 제공해야 한다.
- `ApprovedConfigurationGenerator`는 ZIP 생성 성공 후 최소 이력을 반환하지만, **A의 승인 조회·이력 저장 트랜잭션과 다운로드 응답**은 아직 연결되지 않았다. 서버의 GENERATED 상태를 브라우저 수신·PC 적용으로 해석하지 않는다.
- Preview 비교용 기존 파일 내용과 Diff는 DB·로그·캐시에 저장하지 않는다. 현재 Secret 검사는 알려진 패턴만 탐지한다.
- 메모리 내 Preview 크기 예산은 구현됐다. HTTP 요청 본문 **전체 JSON 바이트** 1 MiB 제한과 413 오류 매핑은 공개 API를 만들 때 별도로 적용해야 한다.
- 권한 정책 선택과 파일 다운로드 최종 승인은 별도 행위다. 승인 메타데이터와 Preview ID·지문·만료를 검사하는 B 내보내기 경계는 구현됐지만, 신뢰할 승인 레코드의 조회·저장과 인증/소유권 검사는 A 연동 전까지 미완료다.
- Preview 신선도 판정은 B 메모리 코드로 준비됐다. A의 현재 스냅샷·Preview 메타데이터와 실제 승인 레코드를 인증된 트랜잭션에서 읽어 이 판정에 연결해야 한다.
- 같은 레포 안에서 A·B는 `services/core-api`, AI 담당은 독립 `ai-service`를 사용한다. 실제 AI 서버와 DB 연동은 현재 B 코드에 연결되지 않았다.
