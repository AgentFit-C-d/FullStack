# 중간 발표 이후 진척: 새 주제 2장

기존 발표의 프로젝트 맞춤 추천 흐름, 카탈로그 구조, 권한·Preview 설명과 겹치지 않도록 **실제 연동에서 발견한 계약 문제**와 **실물 후보의 검증 범위**에 집중한다. 현재 코드와 검증으로 확인한 사실만 사용한다.

## 슬라이드 1 — AI 서버 교체 전, 응답의 의미부터 맞추기

**화면 문구**

- 별도 AI는 검색용 `needs[]`를 반환, B 추천은 9종 Capability 판정을 사용
- B에 Bearer 인증·마감 시각·예산 lease·근거 ID 변환 클라이언트 구현
- 현재 실행 서버의 9종 판정은 유지해 실물 Skill 추천을 로컬에서 검증
- 별도 AI 교체에는 A의 예산 lease와 필수·선택·미정 판정 계약 필요

**발표 대본**

“기능을 연결하면서 같은 ‘필요 기능’이라는 말에도 두 서버의 데이터 의미가 다르다는 점을 확인했습니다. 별도 AI는 Skill 검색에 쓸 키워드를 보내지만, B는 그 기능이 필수인지 선택인지와 근거를 알아야 추천을 판정합니다. 현재 실행 중인 FastAPI는 9종 판정을 제공하므로 이 경로로 실물 Skill 추천을 로컬 검증했습니다. 별도 AI 저장소의 검색 결과를 필수 기능으로 자동 변환하지는 않았고, 서버 교체에 필요한 예산·판정 계약은 명시했습니다.”

**도식 제안:** 왼쪽 `확정 사실` → 가운데 `검색 needs[]` → 오른쪽 `추천 판정에 필요한 9종 Capability`. 가운데와 오른쪽 사이에 `의미 계약 확정 필요` 표시. 추천 엔진 전체 흐름도는 다시 그리지 않는다.

## 슬라이드 2 — 실물 Skill의 지원 범위를 증거로 제한하기

**화면 문구**

- skills.sh에서 받은 TDD Skill을 파일 해시로 고정
- Windows + Claude Code `2.1.310`에서 테스트 작성 기능만 로컬 검증
- 편집·테스트 실행 권한은 `ASK` 또는 `DENY`; 위험도는 `MEDIUM`
- 단일 Skill 구성만 확인, 복수 도구 조합과 테스트 실행 기능은 미검증
- 로컬 AI→PostgreSQL 추천·미리보기와 권한→승인→ZIP 검증

**발표 대본**

“외부 디렉터리에 Skill이 있다고 해서 곧바로 모든 환경에 추천하지 않았습니다. 파일을 고정하고 로컬 Claude Code 버전에서 테스트 작성 기능만 확인했습니다. 이 후보를 로컬 카탈로그로 연결한 뒤 실제 AI 응답에서 PostgreSQL 추천 저장과 미리보기까지 검증했고, 권한 선택·승인·ZIP 생성도 확인했습니다. 테스트 실행 기능이나 다른 도구와의 조합은 증명되지 않았으므로 미충족 경고를 유지합니다.”

**도식 제안:** `고정 파일/버전` → `단독 실행 근거` → `권한·위험도 기록` → `독립 승인 대기`의 짧은 증거 체인. 수많은 Skill을 모두 저장했다는 표현은 사용하지 않는다.

## 발표 전 확인

- 별도 AI 클라이언트가 **추천 생성 API에 아직 연결되지 않았음**을 유지한다.
- 새 후보 해시 `e220a4a01e8865779c78464e722dbb24dff112c7e44475c284a54c4316661527`는 파일 무결성 값이며, 로컬 기능 검증을 팀의 독립 승인으로 표기하지 않는다.
