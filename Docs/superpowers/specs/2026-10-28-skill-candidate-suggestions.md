# skills.sh 후보와 프로젝트 필요 기능 연결

## 목표

확정 기획에서 생성·저장된 9종 Capability 판정과 skills.sh 후보를 같은 프로젝트 화면에서 연결한다. 사용자는 관련 후보의 근거와 아직 확인되지 않은 조건을 보고 선택한 Skill을 ZIP으로 받을 수 있다.

## 현재 경계

- B의 기존 `RecommendationEngine`은 Catalog의 지원·권한·조합 정보를 사용하고 결과를 PostgreSQL에 저장한다.
- skills.sh 후보 스냅샷은 ID·이름·출처·해시만 가진다. 이 정보만으로 OS·Claude Code 버전·의존성·권한의 적합성을 확정하지 않는다.
- 이미 구현된 후보 ZIP은 사용자 선택·고정 해시를 요구하며, 승인된 추천 결과의 Preview/승인/다운로드 기록과 별개다.

## 이번 단계

1. 소유권 확인을 마친 프로젝트의 최신 저장 Capability와 후보 스냅샷을 대조한다.
2. 이름 규칙에 맞는 후보를 `RELATED_CANDIDATE`로 표시하고 어떤 Capability와 연결됐는지 반환한다. 이름만으로 기능 제공을 확정하지 않는다.
3. 필수 Capability의 이름 규칙상 커버리지를 바탕으로 중복을 줄인 조합 후보를 만들되, 의존성·충돌·환경·권한 정보가 없는 조합은 `UNCONFIRMED`로 표시한다.
4. 프론트에서 저장된 추천 결과 아래에 관련 후보를 보여주고, 후보 선택 ZIP을 재사용한다.

## 다음 연결

SKILL.md 및 공급자 감사 결과를 고정 해시로 수집하고, 기능·환경·권한·의존성 정보를 보강한 후보를 기존 조합 판정·Preview·PostgreSQL 추천 이력에 통합한다. 이 단계가 끝나기 전에는 관련 후보를 기존 추천 도구로 가장하지 않는다.
