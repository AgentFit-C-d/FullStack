# 분석 확인용 프론트엔드 설계

## 의도

로그인한 사용자가 프로젝트를 만들고 기획서를 업로드한 뒤 AI 분석을 시작하고, 처리 상태와 분석 결과를 확인할 수 있는 최소 제품 흐름을 제공한다. 추천 기능과 추천 결과 화면은 이번 범위에서 제외한다.

## 목표

- 세션 기반 로그인 상태를 확인하고 GitHub 로그인으로 이동할 수 있다.
- 프로젝트 생성 또는 기존 프로젝트 선택 후 기획서 파일/텍스트를 업로드할 수 있다.
- 현재 프로젝트 버전을 기준으로 분석을 시작할 수 있다.
- 분석 진행 상태를 주기적으로 조회하고 성공/실패/시간 초과 상태를 사용자에게 보여준다.
- 백엔드에 실제 결과 조회 계약이 생기기 전까지는 분석 시도 메타데이터를 명확히 보여주며, 결과 영역은 준비 상태를 안내한다.

## 제외 범위

- 채용 공고 추천, 스킬 추천, 추천 점수 화면
- AI 결과를 프론트에서 임의로 생성하거나 하드코딩하는 동작
- 백엔드의 결과 저장 모델/조회 API 구현
- 자체 아이디·비밀번호 인증 UI (현재 백엔드는 GitHub OAuth 세션을 사용)

## 구현 방식

`apps/web`에 React + Vite 단일 페이지 앱을 추가한다. 브라우저의 `fetch`로 Spring Core API를 호출하며 세션 쿠키를 유지하기 위해 `credentials: 'include'`를 사용한다. 화면 상태는 로그인 확인, 프로젝트 선택, 입력 업로드, 분석 처리, 분석 확인의 단계형 상태로 관리한다.

## API 흐름

1. `GET /api/auth/get-session`으로 세션을 확인한다.
2. 비로그인 상태면 `/api/oauth2/authorization/github` 로그인 버튼을 보여준다.
3. 로그인 상태면 `GET /api/projects`로 프로젝트 목록을 불러온다.
4. 프로젝트 생성은 `POST /api/projects`를 사용한다.
5. 기획서 업로드는 `PUT /api/projects/{projectId}/planning-input` multipart 요청을 사용한다.
6. 분석 시작은 `POST /api/projects/{projectId}/analysis-attempts`로 호출한다.
7. `GET /api/projects/{projectId}/analysis-attempts/latest`를 일정 간격으로 조회한다.
8. 성공 시 현재는 분석 시도 메타데이터를 표시하고, 실제 결과 API가 추가되면 같은 결과 패널에 연결한다.

## 화면 구성

- 헤더: AgentFit 이름, 로그인 사용자, 로그아웃/세션 상태
- 시작 화면: 로그인 안내 또는 프로젝트 목록
- 입력 패널: 프로젝트 생성, 기획서 파일 선택, 텍스트 입력, 업로드
- 분석 패널: 분석 시작 버튼, 처리 단계/상태, 재조회 상태
- 확인 패널: 성공한 분석 시도의 프로젝트/상태/시작 시각/오류 코드, 결과 API 준비 안내

## 접근성 및 실패 처리

- 버튼은 처리 중 비활성화하고 현재 단계를 텍스트로 표시한다.
- 인증 만료, 업로드 실패, 분석 중복, 서버 제한, 시간 초과를 각각 사용자 메시지로 표시한다.
- 파일 업로드와 분석 시작 전에는 프로젝트 및 입력 버전을 명시한다.

## 선택한 접근

React + Vite를 선택했다. 현재 웹 앱 폴더가 비어 있고, 이후 분석 상태 polling과 결과 패널을 확장하기 쉽기 때문이다. 서버 렌더링보다 포트폴리오에서 프론트-백엔드 API 연동과 비동기 상태 처리 역량을 보여주기에도 적합하다.
