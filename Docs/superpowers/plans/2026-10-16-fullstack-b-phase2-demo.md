# Full Stack B Phase 2 Demo Integration Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make B's UUID persistence and recommendation/Preview metadata path work with A Phase 2's V5 schema for next week's demo, without editing A-owned files.

**Architecture:** Start B work from `origin/main` so A's Phase 2 UUID schema and adapters are present. Keep B service-facing IDs as strings where A already calls them, parse UUIDs only at B JDBC boundaries, and validate against fresh PostgreSQL. The existing A controller/adapters remain untouched; unready AI and Catalog inputs remain fail-closed.

**Tech Stack:** Java 21, Spring Boot 3.3.5, JDBC, Flyway, PostgreSQL, JUnit 5, Maven.

**Spec:** `Docs/superpowers/specs/2026-10-16-fullstack-b-phase2-demo-design.md`

## Global Constraints

- Do not edit A-owned authentication, project/profile, integration adapter, OpenAPI, V5 migration, or FastAPI files.
- Preserve existing B public service/DTO signatures used by the A Phase 2 adapters.
- Never turn an unapproved Catalog or `CONTRACT_TEST_DOUBLE` AI response into a successful real recommendation.
- Keep existing file bytes, generated bytes, ZIP content, and Diff out of B9 storage and ordinary logs.
- Preserve `Docs/fullstack-b/presentation/` unchanged; it is untracked user material.
- Use Korean Conventional Commit messages. Verify each change before committing.

## Review Focus

- A valid UUID-shaped string bound with `setString` against PostgreSQL UUID project columns must be caught by Task 2's real PG roundtrip test.
- A malformed or foreign project ID must fail before B writes; Task 2 covers both.
- The UUID user actor must be recorded and not narrowed to `long`; Task 3 covers approval/report.
- An injected B child/Audit failure must roll back the caller-owned transaction; Task 4 covers it.
- A successful B unit test with a synthetic Catalog must not be reported as a real user flow; Task 5 records the evidence boundary.
